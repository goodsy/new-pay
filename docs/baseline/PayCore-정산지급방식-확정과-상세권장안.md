# PayCore 정산·지급 방식 — 확정 방향과 상세 권장안

2026-10-03 KST

## 확정 방향

입금 후 지급과 기관 입금 전 선지급을 모두 지원한다. 기준정보/정책 설정에 따라 적용한다. 초기 선지급 미지원이라는 직전 권고는 사용자 결정으로 대체된다.

### 확정: 선지급 거래 기준 3종 지원

사용자 결정: “매입확정, 매입요청, 승인완료된건에 대해서 선지급 하는걸로 결정”. 다음 세 기준을 모두 지원하며 기준정보/정책에서 적용 기준을 선택한다. 직전 assistant의 매입 확정만 우선 지원 권고는 이 결정으로 대체된다.

| 선지급 기준 | 필요한 업무 근거 |
|---|---|
| 승인 완료 | 확정된 승인 금융 사실 |
| 매입 요청 | 확정 승인에 연결된 매입 요청의 외부기관 전송 완료 근거 |
| 매입 확정 | 기관의 거래별 매입 확정 결과 |

모드와 선지급 기준은 다른 축이다. 입금 후 지급/선지급 모드 중 선지급을 선택한 정책에 위 기준을 연결한다. 명칭 후보는 AUTHORIZATION_COMPLETED / ACQUISITION_REQUESTED / ACQUISITION_ACCEPTED이며 코드 enum은 구현 시 고정한다.

세 기준은 각각 별도의 지급을 발생시키지 않는다. 동일 거래가 승인 완료→매입 요청→매입 확정으로 진행되어도 동일 채무의 선지급은 중복되지 않아야 한다. 선지급 기준은 최소 선행 근거이며 자동 즉시 송금을 뜻하지 않는다. 정산 계산·채무 확정·지급일·한도·재원·보류·취소액 검사는 계속 필요하다.

### 확정: 매입 요청 인정 시점 = 외부기관 전송 완료

사용자 결정: “외부기관에 전송완료”. 매입 요청 기준의 선지급은 외부기관 전송이 완료된 거래를 대상으로 한다. 직전 assistant의 기관 접수 ACK 기준 권고는 채택하지 않는다. 내부 요청 저장/파일 생성만으로 충족되지 않으며 기관의 업무 접수 ACK나 거래별 매입 확정까지 기다리는 것도 요구하지 않는다.

전송 완료는 해당 Adapter의 규약으로 확인하고 영속화한다. SFTP에서는 확정된 파일 전체 업로드 및 기관과 약정한 게시 절차(최종 경로/이름 또는 완료 marker)가 완료됐다는 전송 근거를 사용한다. 이는 기관의 업무 접수 ACK가 아니라 전송 채널 단계의 완료다. 전송/게시 중 연결 단절로 완료 여부를 확인할 수 없다면 불명확 상태를 유지하고 원 제출/파일로 확인한다. 단순 시작·부분 업로드·미확인 전송을 완료로 승격하지 않는다.

파일 Submission의 전송 완료는 해당 확정 파일에 실제 포함된 거래에만 연결한다. 파일 membership·hash·전송 근거와 완료 시각을 보존한다. 향후 다른 채널의 전송 완료 근거는 Adapter별 계약에서 정의하고 업무 응답/접수 ACK와 구분한다. 라이브러리 송신 호출 성공만으로 전송 완료가 증명된다고 가정하지 않는다.

승인 결과 UNKNOWN은 승인 완료가 아니다. 매입 UNKNOWN/REJECTED 상태가 승인 기준 선지급에도 보류를 유발하는지는 별도 위험 정책으로 정한다. UNKNOWN 매입을 매입 확정으로 승격하지 않으며, 기관 미입금/취소/사후 차감의 회수 정책도 별도 결정한다.

## 상세 권장안 — 아직 별도 채택 대상

### 모드 및 정책 연결

- 지급 적격성 정책의 모드 후보: AFTER_PROVIDER_RECEIPT / PREFUNDING. 명칭은 구현 후보다.
- 정책 정의는 MASTER, 실제 적용 Snapshot·적격성 판단·한도 점유·지급 결과·자금 대사는 FINANCIAL 소유다.
- ContractServiceAgreement + MID + Currency 범위의 명시적 Assignment로 적용할 것을 권장한다. GID/Default 자동 상속은 없다. 중복 적용 기간/우선순위를 확정한다.
- 정책은 Version/EffectivePeriod로 관리하고 이미 확정되거나 실행 중인 채무/지급을 새 모드로 조용히 바꾸지 않는다. 적용 시점과 기존 미지급 채무의 전환 절차는 별도 결정한다.

### 입금 후 지급

매입 등 거래 적격성 확인 → 정산 계산/채무 확정 → 기관 입금의 신뢰 가능한 증거와 대상 배분·대사 확인 → 지정 지급일/보류/계좌/재원 조건 검사 → 지급.

입금 확인은 기관 지급예정 파일만으로 완료하지 않고 은행 입금 및 기관 명세를 연결한다. 일괄/수수료 차감 입금의 거래 배분, 차이·부분 입금의 지급 범위를 별도 확정한다. 거래 총액과 은행 입금액이 단순히 같아야 한다고 가정하지 않는다.

### 선지급

선지급 적격 거래 및 정산 근거 확인 → 지급채무 확정 → 선지급 한도/사용 가능 재원 원자 점유 → 지정 지급일/보류/계좌 조건 검사 → 지급 → 이후 기관 입금 배분·대사 → 해당 선지급 노출 해소.

- 승인 완료·매입 요청·매입 확정의 세 기준과 매입 요청의 외부기관 전송 완료 경계는 위 사용자 결정으로 확정됐다. Adapter별 전송 근거 및 부정/불명확 결과의 보류 규칙은 별도 구체화한다. 승인/매입 UNKNOWN을 성공으로 간주하지 않는다.
- 기관 미입금 노출과 지급 실행을 연결하고 정책상 한도 범위에서 경쟁 지급을 직렬화한다.
- 지급이 UNKNOWN이면 자금 예약과 실행 Claim을 유지한다. 만료/Worker 재시작만으로 해제하거나 새 송금을 만들지 않는다.
- 기관 입금 때 같은 가맹점 채무/지급을 다시 생성하지 않는다. 선지급된 거래의 기관 미수/자금 노출을 해소한다.
- 기관 입금이 지연/차감/취소되면 노출·보류·조사 이력을 유지한다. 가맹점 회수/이월/법적 상계는 계약에 따른 별도 정책이다.
- 상계로 가맹점 채권을 회수했다고 기관 미수금까지 자동 소멸시키지 않는다. 두 자금 사실을 구분한다.

### 공통 구분

정산 방식(입금 확인/선지급)과 정산 주기(D+N·주간 등)는 다른 축이다. 계산 기준일, 확정 시점, 예정 지급일, 입금 조건, 실제 지급일을 각각 보존한다. 지급 보류는 채무 삭제가 아니다.

한도는 건별/기간별 지급 한도와 미입금 선지급 노출 한도를 구분한다. 기관 순입금·수수료·보류금 차이를 반영한 노출 계산, 해소/예약 해제, 전체 PG 재원·기관·가맹점·MID별 범위는 다음 정책 설계에서 확정한다. 운영 한도 수치는 본 문서에서 생성하지 않는다.

## 가상 기관 필수 시나리오

1. 입금 후 지급: 입금 전에는 채무 보존/지급 대기, 검증된 입금 후 한 번 지급.
2. 선지급: 입금 전 한도·재원 내에서 지급, 입금 후 재지급 없이 노출 해소.
3. 두 지급의 동시 한도 점유, 은행 성공 후 응답 유실, 한도 초과·재원 부족.
4. 부분 입금·기관 차감·입금 지연·후발 취소·지급 반환.
5. 정책 버전/모드 변경과 이미 실행 중인 지급, 중복 입금 파일·은행 내역.
6. 세 선지급 기준별 대상 선택, 승인→매입요청→매입확정 진행 시 동일 거래의 중복 채무/지급 방지.
7. 선지급 이후 매입 거절·UNKNOWN·후발 취소의 노출/보류/회수 이력과 정책 변경 검증.
8. 파일 생성·부분 업로드는 요청 기준 미충족, 전체 전송/게시 완료는 충족, 기관 접수 ACK 지연만으로 완료된 전송을 미완료로 바꾸지 않음. 전송 불명확 조회 복구 및 파일에 미포함된 거래의 오선지급 방지.

가상 은행/기관 기록은 PG와 별도로 영속한다. 정책 설정은 허용 조건이며 재원·기관 근거·계약·통제의 검증을 대체하지 않는다.
