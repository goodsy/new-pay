# 06. Reliability / Recovery Architecture

## 목적

실패 시 상태를 잃지 않고, 복구 과정에서 중복 승인·정산·지급을 만들지 않는 절차를 정의한다.

## 범위

장애 격리, 결과 불명확 거래, 재처리, 백업·복원, 대사 및 재해 복구를 다룬다.

## 핵심 규칙

- 승인 지연·성공률 SLO, 데이터 손실 허용 RPO, 복구 시간 RTO는 플랫폼별로 합의하고 측정한다. 기관 SLA와 내부 SLO를 구분한다.
- 승인·이벤트·정산·지급의 장애를 별도 상태와 알림으로 관리한다. 금융 후속 처리 지연을 결제 실패로 바꾸지 않는다.
- Outbox 적체는 보존·재전달한다. 용량·최고 연령·복구 처리량에 한계를 두고 저장소 고갈 전 제한 정책을 적용한다.
- 단일 활성 지급 실행 또는 fencing 가능한 점유를 사용한다. Lease 만료만으로 이전 실행자가 기관 호출을 하지 않았다고 가정하지 않는다.
- 불명확 Attempt는 동일 기관 ID 조회·통보·대사로 복구한다. 작업 재시작이 외부 요청 재실행과 같아서는 안 된다.
- 정산 보정은 이력 있는 Adjustment로 수행한다. 확정·지급된 과거 결과를 파괴적으로 덮어쓰지 않는다.
- DB별 백업·PITR·복원 검증을 제공한다. 세 DB를 같은 시각으로 복구할 수 있다고 가정하지 않고 정책 버전·이벤트 ID·watermark로 재동기화한다.
- Outbox/Inbox 보존과 브로커 보존은 최대 복원·재생 기간을 충족한다. 복원으로 중복 기록이 과거로 돌아갈 수 있으므로 외부기관 거래 근거와 지급 효과를 추가 대사한다.
- 복원 후에는 외부 승인·지급 전송을 중지한 채 재생·대사를 먼저 수행한다. Projection 재생은 외부 금융 호출을 실행하지 않는다.

## 예시 흐름

| 장애 | 즉시 동작 | 복구 및 완료 근거 |
|---|---|---|
| MASTER 중단 | 로컬 스냅샷의 유효기간·차단 정책 적용 | 누락 설정 버전 수신·긴급 폐기 검증 |
| Financial 중단 | 승인 지속, Outbox 보존, 후속 금융 처리 보류 | 적체 해소·건수/금액 대사 |
| 브로커 중단 | PAYMENT 커밋 지속, Relay backoff | 내구성 전송 확인·누락 검사 |
| 기관 응답 유실 | 결과 불명확, 무조건 재승인·재지급 금지 | 기관 조회·통보·대사로 확정 |
| PAYMENT DB 실패 | 신규 승인 안전 중단, 기존 Attempt 조사 | DB 복구·기관 성공 거래 보완 |
| FINANCIAL 복원 | 지급 송신 중지, 소비 재개 범위 설정 | Inbox 재생·은행 지급 대사·승인 후 송신 재개 |

### 복원 절차

```text
영향 범위 확인 → 외부 금융 송신 차단 → 복구 지점·백업 검증
 → DB 복원 → 설정 버전 복구 → 이벤트/Projection 재생
 → 기관 거래·정산·지급 대사 → 차이 보정 및 승인
 → 제한된 트래픽으로 재개 → 모니터링·사후 기록
```

재생 기간의 취소·부분취소와 이미 지급된 금액을 함께 검사한다. DB에 지급 기록이 없다는 사실만으로 재지급하지 않는다.

## 금지사항

- timeout 거래를 모두 실패 처리하고 재실행하는 것.
- 운영 DB 복원 직후 배치를 자동 실행하는 것.
- Outbox·Inbox·Job 실행 기록을 장애 해결 목적으로 지우는 것.
- 백업 생성 성공만으로 복원 가능성을 인정하는 것.

## 구현 체크리스트

- [ ] 플랫폼별 SLO/RPO/RTO와 소유자를 승인했다.
- [ ] 기관 성공 후 저장 실패, ACK 유실, Worker 종료를 훈련했다.
- [ ] 독립 DB 복원 후 정합성·중복 지급 방지를 검증했다.
- [ ] 용량 한계·재생 기간·복구 처리량을 측정했다.
- [ ] 지급 재개 승인과 금융 차이의 해소 근거를 기록한다.
