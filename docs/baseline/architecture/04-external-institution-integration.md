# 04. External Institution Integration

## 목적

VAN·카드사·은행의 통신 규약을 내부 도메인과 분리하고, 외부 금융 효과를 안전하게 추적한다.

## 범위

승인·취소·매입·계좌환불·지급, 요청/조회/통보/파일 연동과 기관별 운영 제약을 다룬다.

## 핵심 규칙

- Domain은 내부 명령·결과·식별자를 사용한다. 기관 DTO, 응답 코드, SDK 및 전문 형식은 Adapter에서 변환한다.
- Port는 authorize, cancel, queryResult, submitAcquisition, requestPayout 등 업무 의도로 정의한다. 기관별 인증·전문·타임아웃은 Adapter 책임이다.
- 내부 결과는 성공/명시적 실패/결과 불명확을 구분한다. 타임아웃·연결 단절은 기관 거절과 다르다.
- 외부 호출 전 안정적인 요청 식별자와 Attempt를 소유 DB에 기록한다. 같은 업무의 복구에 새 지급 ID·새 승인 ID를 무조건 생성하지 않는다.
- 기관의 멱등성·결과조회·중복 검출 능력을 연동 명세와 인증 시험으로 확인한다. 지원하지 않으면 자동 재호출 범위를 제한하고 조회·대사·운영 확인으로 해소한다.
- 승인 도중 타임아웃이 나면 다른 VAN으로 자동 재승인하지 않는다. 첫 기관에서 성공했을 가능성이 있다. 라우팅 전환은 전송 전 실패가 확실하거나 미승인이 확인된 조건에서만 허용한다.
- 상태 확정은 응답, 서명 검증된 통보, 결과 조회, 기관 대사 중 신뢰 가능한 근거와 상태 전이 규칙에 따른다. 상충하는 결과는 보류·조사한다.
- 기관별 connection/read/전체 deadline, 동시성, rate limit, circuit breaker와 retry 예산을 정의한다. Read 작업과 자금 효과 Write 작업의 재시도 정책은 다르다.
- 통보는 인증·서명·timestamp·nonce를 검증하고 내구성 있게 기록한 뒤 응답한다. 중복·지연·역순 통보를 허용 가능한 전이로 처리한다.
- 파일은 기관·업무일·회차·파일 ID·hash·건수·합계를 기록한다. staging 검증 후 반영하며 동일 ID·다른 hash는 격리한다. 송신 파일도 생성·전송·접수·업무 결과를 구분한다.

## 예시 흐름

```text
Payout Attempt 저장 → 은행 요청 → timeout
 → Payout 결과 불명확 / 재지급 잠금
 → 동일 기관 요청 ID로 결과조회
 → 성공이면 FINANCIAL 로컬 상태 확정 + Outbox
 → 조회 불가이면 은행 대사·운영 확인 후 해소
```

카드 승인도 같은 원칙을 적용한다. 기관 성공 후 PAYMENT 커밋 실패는 원래 Attempt로 조회하여 Authorization과 이벤트를 복구한다. 미확정 거래는 가맹점 조회 API에 명확히 표현한다.

## 금지사항

- 기관 DTO가 Domain·Application의 업무 모델을 대체하는 것.
- 모든 timeout을 실패로 표시하고 새로운 거래로 재시도하는 것.
- 전문 원문에 카드·인증정보를 무제한 로그로 남기는 것.
- 접수 ACK를 매입 완료·지급 완료로 해석하는 것.

## 구현 체크리스트

- [ ] 기관별 요청 ID·조회·중복·통보·파일 규약을 정리했다.
- [ ] 성공·거절·불명확 결과 변환과 상충 결과 처리가 있다.
- [ ] 인증서 만료·망 장애·기관 지연·파일 재수신을 시험했다.
- [ ] 연동 인증 환경과 운영 전환 승인 증거를 보관한다.
- [ ] 긴급 중단·우회 조건·기관 연락·수동 해소 절차가 있다.
