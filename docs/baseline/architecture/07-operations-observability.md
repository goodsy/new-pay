# 07. Operations / Observability

## 목적

승인 장애와 금융 데이터 차이를 조기에 발견하고 통제된 운영 명령으로 해소한다.

## 범위

로그·지표·추적·감사, 대사, 관리 화면, 재처리 및 Runbook을 다룬다.

## 핵심 규칙

- correlationId/causationId와 paymentId, attemptId, eventId, settlementId, payoutId를 연결한다. 추적은 비동기 경계에서도 이어진다.
- 구조화 로그는 진단용, 감사 기록은 행위 증거용, 금융 기록은 금액 정합성용이다. 세 역할을 혼동하지 않는다.
- 거래 ID를 지표 label로 사용해 고카디널리티를 만들지 않는다. 거래별 검색은 접근 통제된 로그·조회 도구를 사용한다.
- 승인 API는 소유 PAYMENT 조회 모델로 응답한다. 가맹점 통합 조회는 Financial Projection의 지연·기준 시각을 표시한다.
- 운영 도구는 소유 플랫폼 Application Use Case를 호출한다. 요청 ID·대상 범위·사유·권한·승인·결과·재시도 여부를 남긴다.
- 재처리는 dry-run, 대상 미리보기, 건수/금액 한도, 중단, 승인, 실행 이력을 제공한다. 정산 재산출·Projection 재생·기관 재전송은 별도 명령이다.
- 대사는 소유 플랫폼의 이벤트·서명된 추출물·기관 원장으로 수행한다. Reconciliation이 PAYMENT DB에 직접 접속하지 않는다.
- 대사 파일·추출물에는 기준 기간·시간대·생성 cutoff·완전성 표식을 둔다. 총계 비교와 거래 단위 누락·중복·금액 차이 검사를 함께 한다.

## 예시 흐름

| 관측 대상 | 주요 지표 | 알림 후 동작 |
|---|---|---|
| Payment | p95/p99 응답, 내부 오류, 기관 거절, 불명확 Attempt 수·연령 | 기관/내부 장애 분리·안전 차단 |
| Event | Outbox 최고 연령·용량, consumer lag, Inbox 실패, DLQ | 누락·원인 확인, 제한된 재처리 |
| Financial | 미매입, 미정산, 예정일 초과, 미확정 지급, 대사 차이 | 업무일·마감 기준 조사 및 보류 |
| Infra | DB 풀 대기, lock/deadlock, 저장소, CPU, 백업·복원 결과 | 자원 제한·복구 절차 |
| Security | 인증 실패, 권한 위반, 중요 변경, 비밀 만료 | 차단·회전·감사 조사 |

```text
Financial 이벤트 지연 알림
 → 정상 승인 건수와 Outbox 상태 확인
 → Inbox 실패 원인 확인 / 지급 마감 영향 판단
 → 승인된 범위 재처리
 → 거래 단위 및 건수·금액 대사
 → 경보 해제 + 감사·사후 분석
```

경보는 소유자, 심각도, 실제 업무 영향, Runbook을 연결한다. 지표가 정상으로 돌아온 것과 금융 차이가 해소된 것은 별도 완료 조건이다.

## 금지사항

- 운영자가 직접 SQL UPDATE로 거래 상태·정산금액을 고치는 것.
- 로그 검색 결과만으로 지급 성공을 확정하는 것.
- 대사 총액이 같다는 이유로 거래 단위 차이를 무시하는 것.
- 관리자 조회가 승인 DB에 대량 부하를 주는 것.

## 구현 체크리스트

- [ ] 경계 간 추적과 민감정보 마스킹을 검증했다.
- [ ] 지연·불명확 거래·마감 초과·대사 차이 알림을 제공한다.
- [ ] 재처리·조정·지급 보류 도구에 권한·승인·감사가 있다.
- [ ] 업무 시간대·거래일·기관일·마감 cutoff를 정의했다.
- [ ] Runbook에 조사·조치·정합성 완료 조건이 있다.
