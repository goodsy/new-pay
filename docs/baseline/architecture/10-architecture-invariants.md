# 10. Architecture Invariants

## 목적

설계·코드·배포·운영에서 지켜야 할 불변 규칙과 검증 방법을 고정한다.

## 범위

DB, 트랜잭션, 이벤트, 도메인, 기관, 보안, 금융 통제 및 변경 관리에 적용한다. 규칙을 바꾸려면 [README의 변경 절차](README.md)를 따른다.

## 핵심 규칙

| ID | 불변 규칙 | 검증 증거 | 담당 영역 |
|---|---|---|---|
| INV-01 | 운영 MASTER/PAYMENT/FINANCIAL은 물리 분리하고 각각 원본 소유권을 갖는다 | 인프라 구성·DB 권한·격리 시험 | 플랫폼 |
| INV-02 | PAYMENT ↔ FINANCIAL 직접 조회·쓰기·JOIN을 금지한다 | 연결 설정·네트워크 거절·코드 검사 | 데이터 |
| INV-03 | Cross-DB Transaction/XA/2PC를 금지한다 | DataSource·트랜잭션 구성 검사 | 데이터 |
| INV-04 | 승인 확정의 Payment/Authorization/Outbox는 동일 PAYMENT 로컬 트랜잭션이다 | 중간 실패 주입·원자성 테스트 | 결제 |
| INV-05 | Financial Inbox 완료·업무 효과·후속 Outbox는 별도 FINANCIAL 로컬 트랜잭션이다 | commit/ACK 경계 장애 시험 | 금융 |
| INV-06 | 전송 중복은 허용하되 금융 효과 중복은 막는다 | Inbox+업무 Unique Key·동시 요청 시험 | 통합 |
| INV-07 | Financial 장애·Batch 부하는 승인 경로의 동기 의존성이 아니다 | 장애·부하 격리 시험 | 플랫폼 |
| INV-08 | Domain은 기술 객체·외부기관 DTO에 의존하지 않는다 | ArchUnit·의존성 검사 | 도메인 |
| INV-09 | Batch는 실행 조정만 하고 도메인 로직을 소유하지 않는다 | 리뷰·Domain 테스트·Batch 경계 검사 | 금융 |
| INV-10 | 정책은 버전으로 식별하고 과거 거래 계산 근거를 보존한다 | 정책 변경 후 재현 시험 | 정책 |
| INV-11 | 외부 timeout은 결과 불명확이며 자동 재승인·재지급 근거가 아니다 | simulator·기관 결과조회 시험 | 기관 연동 |
| INV-12 | 승인·매입·정산·지급은 독립 상태이며 완료를 서로 추정하지 않는다 | 상태 전이·부분 실패 시험 | 도메인 |
| INV-13 | 금융 차이는 대사로 탐지하고 조정·해소 이력을 남긴다 | 거래별·합계 대사·감사 | 금융 통제 |
| INV-14 | 조회·명령은 MID 소유권·최소 권한을 검사한다 | 교차 MID 부정 테스트 | 보안 |
| INV-15 | 중요 조정·계좌 변경·지급 재개는 통제된 승인과 감사가 필요하다 | 권한·이중 승인·변경 이력 시험 | 운영 |
| INV-16 | 복원·재생은 외부 금융 효과를 무조건 재실행하지 않는다 | PITR 후 기지급 거래 시험 | 복구 |
| INV-17 | Production MID는 계약 승인 후 발급하고 테스트 식별자와 구분한다 | 온보딩 상태·환경 격리 시험 | Master |
| INV-18 | 모듈 간 접근은 공개 API/Event/Port이며 Repository 직접 접근을 금지한다 | Modulith·빌드 의존성 검사 | 아키텍처 |
| INV-19 | 호환성·정합성 검증 없이 스키마·이벤트·원본 경계를 변경하지 않는다 | CI 관문·cutover 대사·ADR | 배포 |

DB 접근은 Port 뒤에 숨겼다는 이유로 허용되지 않는다. Port 구현도 소유권 규칙을 따라야 한다. 공용 `shared` 모듈은 금액·식별자 등 최소 공통 개념만 제공하며 타 도메인 Aggregate·Repository의 우회 통로가 되어서는 안 된다.

## 예시 흐름

```text
정산 기능 제안
 → INV-01/02: 로컬 Projection으로 대상 선택
 → INV-05/06: Inbox·업무 키·로컬 트랜잭션 설계
 → INV-09/10: Domain에서 보존한 정책 버전으로 계산
 → INV-12/13: 매입·정산·지급 상태 구분 및 대사
 → INV-07/16/19: 격리·복원·배포 검증 후 구현 승인
```

코드 리뷰는 적용 INV와 테스트 근거를 함께 기록한다. 자동 검사로 증명할 수 없는 의미 규칙은 업무 테스트·리뷰·운영 훈련으로 검증한다.

## 금지사항

- 일정·성능을 이유로 규칙 위반을 문서 없이 영구화하는 것.
- 직접 DB 조회를 Adapter·Port로 감싸 허용하는 것.
- 자동 검사 통과만으로 금융 정합성·기관 동작을 보장한다고 주장하는 것.
- 운영 복구를 위해 상태·멱등성·감사 기록을 삭제하는 것.

## 구현 체크리스트

- [ ] 기능별 적용 INV와 담당자가 명시되어 있다.
- [ ] 규칙마다 자동 검사 또는 구체적인 검증 증거가 있다.
- [ ] 예외·변경은 ADR, 기간, 보완 통제와 해소 책임자를 갖는다.
- [ ] CI·운영 검토에서 위반을 탐지하고 배포를 차단한다.
- [ ] 기준선 변경 시 모든 관련 문서·검증을 함께 갱신한다.
