## 2. 정리 원칙

1. **업무 단위로 묶는다** — 회사 / 대표자 / 담당자, 가맹점은 개요 / Site·계약 / MID·개통 / 한도 / 변경 이력. 참고 자료의 '회사정보'·'이용정보' 묶음을 따른다.
2. **머리에 '지금 상태'와 '기다리는 일'** — 이름·코드·상태 배지·사업자 링크, 승인 대기·결과 확인 필요를 머리에 둔다(참고 자료의 MID 선택 + 계약상태 배지 + 계약일).
3. **한 사실은 한 곳에** — 같은 표가 두 번 나오거나(통화), 같은 대상이 여러 표에 반복되거나(Site 4곳, Site 심사가 MID마다 반복) 하지 않게 한다.
4. **내부 키·기술 상태는 보이지 않게** (D-ADMIN-UI-004 ③, D-ADMIN-UI-005, D-ADMIN-UI-007 ③) — 사람이 읽는 값(채널 식별값·가맹점 코드·서비스 종류·MID)으로 바꾼다. 기술 상태는 접힌 "기술 정보"에만 둔다(D-ADMIN-UI-009 ②).
5. **늘 같은 값과 늘 빈 칸은 보이지 않게** — 정보가 없는 칸은 운영자의 눈만 쓴다. 다만 '오해를 막는 문구'(예: 등록 완료 ≠ 진위확인)는 남긴다.
6. **작업은 대상 옆에, 안전 장치는 그대로 따라간다** — 2인 승인 요청·1인 명령 버튼은 대상 행이나 섹션의 '변경'·작업 칸에 둔다. 결과 불명 잠금("같은 내용 다시 보내기"), 되돌릴 수 없음 확인, 감사 안내 문구, 등록자≠승인자 근거(등록자 열)는 줄이지 않고 위치만 옮긴다(ADMIN-DS-001 §5 "금융 안전 장치는 모양 정리 때 바꾸지 않는다").
7. **없는 데이터를 꾸미지 않는다** — 정산·수수료·카드사별 이용 가능 같은 업무 항목은 데이터가 생길 때 연다(§5).

```

```
탭 순서의 근거는 운영 흐름이다: 등록·현황 확인 → Site 심사·계약 승인 → MID 발급·개통 → 한도 → 사후 확인(이력) → 장애 분석(기술).

- **개요**: 서비스 개통 현황(5단계) / 가맹점 코드 [변경](코드 변경 요청, 가능할 때만) + "이전 코드 n개" 접기 / 등록일 / 다음 할 일 한 줄 [추측: 개통 현황에서 계산 — 새 계산이 늘지 않게 기존 serviceOpeningTimeline 값만 쓴다].
- **Site·계약**: Site 표(채널 | 상태 | 심사 | 등록자 | 작업: 심사 승인 요청·심사 거절) → 계약 카드(계약 n · 등록일 | Revision 표 | 서비스: 카드 PG 결제 · 추가일 | 새 Revision 등록).
- **MID·개통**(선택 MID 범위): 결제 생성 조건: 충족/미충족(참고) 요약 → Site 배정 → 결제수단 개통(+개통 등록) → Site 적용 확인 → 통화(한 표, +통화 활성화 요청) → 카드 Route → 개통 점검표. MID 선택은 이 탭이 아니라 상세 머리에 있다(아래 "MID 선택 머리").
- **한도**: 현행 표(범위는 사람용 값). MID 범위 행(MID_OVERRIDE)은 선택 MID의 것만, 가맹점·서비스 범위 행(CSA 기본 등)은 늘 보이며 "가맹점 공통" 표시.
- **변경 이력**: 순번 | 시각 | 대상 | 변경 | 행위자.
- **기술 정보**: 권리 revision·권리 전파(현행 접힘 내용).

**MID 선택 머리(Q-IA-4 답 — 상세 맨 위, 토스식).** 사용자는 권장안(MID·개통 탭 안) 대신 상세 맨 위를 골랐다. 아래는 Coordinator 해석이며, 되돌릴 수 있는 화면 세부(가역 UI 세부)라 이 문서에 적고 구현한다. 금융·권한·감사 의미는 바뀌지 않는다.

- **자리**: 상세 머리 요약(가맹점명·코드·사업자) 바로 아래, 탭 막대 위. 어느 탭을 보고 있어도 보인다.
- **MID 수에 따라**
  - 0개: "발급된 MID 없음" 글과 '첫 MID 발급 요청' 진입(표시 조건·2인 요청 폼은 지금 그대로 — OPERATOR, mayRequestFirstMid).
  - 1개: 선택 상자 없이 그 MID를 고정 표시.
  - 2개 이상: 선택 상자(native select — CSP, 접근 가능한 이름 "MID 선택"). 처음 값은 기본 MID, 없으면 첫 MID.
- **선택 MID 배지**: 상태(StatusBadge), 기본 MID 여부, 발급일, 근거 Revision 번호. 계약 상태 배지는 이번에 하지 않는다(근거 Revision 승인·효력 계산이 새 표시 규칙이 되므로 B4 리뷰에서 따로 본다).
- **선택을 따르는 내용(MID 범위)**: MID·개통 탭 전부(Site 배정·결제수단 개통·Site 적용 확인·통화·카드 Route·개통 점검표), 한도 탭의 MID 범위 행.
- **선택과 무관한 내용(가맹점 단위)**: Site 목록·Site 심사, 계약·CSA, 가맹점·서비스 범위 한도, 변경 이력, 기술 정보. 이 영역에는 "가맹점 공통" 표시를 둔다(선택 MID로 걸러진 것으로 오해하지 않게).
- **상태 보관**: 선택 MID는 화면 메모리에만 둔다(URL·hash·브라우저 저장소 불변 — MERCHANT-DETAIL-VIEW-001과 같은 규칙). 다른 가맹점을 열면 처음 값으로 돌아간다. 내부 키는 DOM에 새로 넣지 않는다(MID는 외부 식별자 — §3.6).
- **안전 장치**: MID별 결과 불명 잠금(activation.<MID>.register)은 MID를 바꿔도 메모리에 남는다. 선택하지 않은 MID에 잠금이 있으면 MID 선택 머리에 "결과 확인 필요" 표시를 둔다(잠긴 폼이 보이지 않는 곳에 숨지 않게 — §7 위험과 대응).

### 7.1 B1 구현 메모(2026-11-24)

- **Site 심사 표 자리**: B4 탭이 생기기 전까지 Site 패널 안, Site 목록 표 바로 아래 "Site 심사" 소제목 아래 한 번. 이유: Site를 보는 곳 바로 옆이 운영자에게 자연스럽고, B4의 'Site·계약' 탭에서도 같은 자리라 다시 옮기지 않는다. 표시 조건은 예전과 같게 **MID가 하나라도 있을 때만**(예전에는 MID "개통" 영역 안에 있었다 — MID 발급 전 심사 버튼을 새로 보이지 않는다).
- **동작 불변**: 결과 불명 잠금 메모리 키 `activation.siteReject.<site>`(App 메모리), 잠긴 폼 다시 열기·다른 Site 거절 막기, 거절 확인 대화상자("되돌릴 수 없습니다…"), 2인 '심사 승인 요청'과 같은 그룹 대기 숨김(C-35), 등록자 열. "대표(PRIMARY)"는 어느 MID의 열린 대표 Site인지로 표시한다(표시만).
- **변경 이력 '변경' 열**: 한국어 이름만. MASTER 변경 종류 34개에 이름을 붙였다(lib/merchantChangeTypes.ts, 용어는 '대상' 열과 같게). 화면이 모르는 새 종류는 코드 그대로 보인다(무엇이 바뀌었는지 숨기지 않는다 — '대상' 열과 같은 규칙).

- **안내문**: 목록·상세 MapNote는 "상세 조회는 감사 기록에 남습니다."만 남겼다("조회 전용"·"개통 상태를 조회"는 사실과 달라 뺐다). 목록 필터 도움말 3줄은 입력 규칙 안내라 B6에서 함께 본다.

### 위험과 대응
- **시험 대량 변경(B4)**: 탭 뒤로 숨은 내용 때문에 단언이 실패한다. 공용 "탭 열기" 시험 도우미를 먼저 만들고, 단언의 의미(무엇이 보이고 무엇이 안 보이는가)는 바꾸지 않는다. 내부 키 비노출·CSP·결과 불명 잠금 시험은 ADMIN-DS-001 §7.1대로 삭제·완화하지 않는다.
- **결과 불명 잠금 영역 이동**: 잠금 상태는 App 메모리(revisionMemory — Revision 폼, activation.* 개통 등록·Site 거절 키)에 있어 위치를 옮겨도 유지된다. 그러나 (1) 탭을 바꿀 때 MerchantActivationArea가 언마운트되면 useOneShot 정리 함수가 '잠기지 않은 결정 결과'를 지운다. (2) 잠긴 폼이 보이지 않는 탭에 숨을 수 있다. 대응: 탭 패널은 언마운트하지 않고 `hidden`으로 숨긴다. 머리에 "결과 확인 필요" 표시와 해당 탭 표시를 둔다. 기존 잠금 동작 시험은 바꾸지 않고 통과해야 한다. Site 심사 표를 MID 영역 밖으로 옮길 때 useLockedSiteReject 메모리 키(activation.siteReject.<site>)는 그대로 둔다.
- **접근성**: 탭은 tablist/tab/tabpanel, aria-controls, 화살표 키, 버튼 전환 뒤 제목 초점(MERCHANT-DETAIL-VIEW-001 MINOR-2 관례)을 갖춘다. 색만으로 상태를 말하지 않는다. CSP 때문에 style 속성은 쓰지 않는다.
- **의미 변화**: 진위확인 배지 제거(Q-IA-2), 번호 조회 즉시 상세(Q-IA-7 대안 A)는 컴플라이언스·감사 의미가 있다 → 사용자 결정 전 구현하지 않는다.
